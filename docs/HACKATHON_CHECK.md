# Проверки перед хакатоном

Проверено на компьютере 8 ноября 2026. Телефон и GitHub не использовались. Основой служит задание: 40 баллов за WER, 25 за диаризацию, по 10 за метки/RTF/UX, 5 за защиту.

## Исправлено в конвейере

1. Пересекающиеся интервалы VAD и одного голоса могли отправить одни сэмплы в ASR несколько раз. Теперь они объединяются до нарезки на фрагменты; предел 24 секунды сохранён. Разные голоса при перекрытии не переназначаются.
2. Сглаживание могло приписать короткий ответ другому голосу даже через паузы. Теперь оно применяется только к непрерывной последовательности трёх соприкасающихся интервалов.
3. Декодер мог бесконечно ждать выход MediaCodec на повреждённом файле, задерживая следующие записи. Если 30 секунд нет ни входного, ни выходного продвижения, задача завершается ошибкой формата. Общая длительность нормального декодирования не ограничена этим таймером.
4. `totalMs`/RTF не включали сохранение расшифровки. Теперь включают его; в метриках есть `saveMs`. Импорт и ожидание очереди по-прежнему не входят в RTF обработки. Если запись отменена до фиксации результата, метрики успешного завершения не создаются.

## Подтверждено проверками

- 28 JVM-тестов прошли: пересечения, паузы, смены голосов, нарезка длинного участка без потери сэмплов, границы аудио, исходная временная шкала, нумерация speaker_1/2/1, JSON, защита от переписывания слов LLM, остановка зависшего декодера и прежние проверки приложения.
- 2 Python-теста валидатора экспорта прошли. Он проверяет точные поля, типы, непустой текст, порядок говорящих, хронологию и, при указанной длительности, выход меток за конец аудио. Настоящие перекрытия разных голосов допустимы.
- Release- и debug-сборки, компиляция Android-тестов и Android Lint прошли без ошибок. Предупреждения Lint остаются. Android-тесты на устройстве не запускались.
- У готового debug APK проверена подпись, SHA-256 всех шести встроенных файлов моделей совпали с `config/models.sha256`. Файл для установки: `artifacts/neuro-steno-hackathon-debug.apk` (847 МиБ).
- Основные модели имеют фиксированные SHA-256 и входят в APK. Подготовка Qwen копирует встроенный файл в память приложения, не скачивает его. Сетевой код приложения используется для необязательной загрузки Whisper; аудио туда не отправляется.

Синтетические данные JVM-тестов проверяют алгоритмы и интеграционные контракты, а не точность нейросетей. Настройки моделей, VAD и кластеризации не подбирались без эталонных диалогов.

## Проверка файла для жюри

```bash
python3 tools/eval/validate_export.py result.json --duration-ms 60000
```

Замените длительность на длительность конкретного аудио. Чтобы проверить только структуру, уберите `--duration-ms`. Если есть эталон, WER и DER считаются существующими `tools/eval/wer.py` и `tools/eval/der.py` после установки их зависимостей.

## Что ещё требует реального устройства и эталона

- Реальные WER, DER, точность временных меток, RTF, потребление RAM и нагрев для трёх записей жюри не измерены.
- Подтверждение импорта трёх записей подряд, полного офлайн-прохода локальной LLM и системного экспорта на целевом телефоне.
- Метки относятся к фрагментам, пословного выравнивания нет. При одновременной речи разных людей ASR получает смешанный звук; разделения аудиоисточников нет.
- Если диаризация не покрыла часть речевого интервала VAD, эта часть пока не распознаётся: автоматически придумывать для неё говорящего без измерений не стали.
- Сглаживание непрерывного короткого переключения (<350 мс) и разрез на 24 секундах требуют проверки на эталоне; возможны потеря короткого ответа и разрез слова на границе.
- Ограничение времени генерации LLM полагается на штатное завершение отмены нативным runtime. Его поведение при сбоях устройства не подтверждено JVM-тестами.

Для установки нужен подписанный APK. Локальный `assembleRelease` без ключа создаёт unsigned APK; debug APK подписывается локальным отладочным ключом. Настройкой release-подписи/CD занимается команда отдельно.
