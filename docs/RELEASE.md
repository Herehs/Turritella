# Выпуск APK по тегу

Workflow `.github/workflows/release.yml` запускается при push тега `v*`. Допустимы `v1.0`, `v1.0.1`; остальные формы отклоняются до сборки. В GitHub Release публикуются подписанный ARM64 APK со встроенными моделями и файл SHA-256. Телефон не требуется: перед публикацией выполняются JVM-тесты и Android Lint.

## Однократная настройка

Создайте постоянный Android signing key либо используйте уже существующий ключ приложения. Сохраните его резервную копию: все обновления должны подписываться тем же ключом. Не коммитьте ключ и пароли.

Добавьте в GitHub → Settings → Secrets and variables → Actions:

| Secret | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Содержимое keystore, кодированное base64 (`base64 -w 0 release.jks` на Linux) |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль хранилища |
| `ANDROID_KEY_ALIAS` | Alias ключа |
| `ANDROID_KEY_PASSWORD` | Пароль ключа |

Ключ извлекается во временный каталог runner и удаляется в шаге `always()`. Без секретов workflow завершается с понятной ошибкой; APK со случайным debug-ключом не публикуется. Локальный `assembleRelease` без переменных подписи создаёт unsigned APK; для установки локальной отладочной сборки используйте `assembleDebug`.

Если установленная ранее версия подписана debug-ключом, выпуск с новым release-ключом нельзя установить как её обновление. Для сохранения совместимости используйте исходный ключ либо заранее экспортируйте записи перед отдельной установкой.

## Выпуск

После отправки изменений workflow в репозиторий:

```bash
git tag -a v1.0 -m "Turritella 1.0"
git push origin v1.0
```

Это запустит сборку и публикацию. Workflow не отправляет теги самостоятельно. Уже опубликованный релиз не перезаписывается: выпустите новый тег.

`versionName` берётся из тега без `v`. `versionCode = major × 1000000 + minor × 1000 + patch`; отсутствующий patch равен нулю. Minor и patch — 0..999, итоговый код — 1..2100000000. `v1.0` и `v1.0.0` означают одну Android-версию; для обновления увеличивайте номер. Для локальной проверки алгоритма:

```bash
python3 -m unittest discover -s scripts -p 'test_release_version.py'
```

Публикующий job получает `contents: write`; сборочный job — только `contents: read`. Используется штатный `GITHUB_TOKEN`, отдельный PAT не нужен. Настройки организации могут ограничивать эти разрешения.
