# Ревью интеграции UI — 8 ноября 2026

Исправлены следующие проблемы:

- **Сообщения:** три экрана выводили `UiMessage.toString()`, а эффекты настроек не собирались. Все 13 сообщений сопоставлены русским строковым ресурсам. Общий SnackbarHost использует цвета surface/text/accent текущей темы. Сообщение настроек закрывает меню, чтобы снэкбар был виден.
- **Навигация и плеер:** ViewModel создавались в Activity store и не освобождались при выходе из заметки. Подключены сохранение состояния и отдельный ViewModelStore на NavEntry. Старый Navigation 3 alpha02 заменён совместимой стабильной 1.0.0 с Lifecycle 2.10.0. Повторное открытие маршрута не создаёт дубликат; повторный Back не удаляет корень.
- **Уведомления:** MainActivity не читала EXTRA_NOTE_ID / EXTRA_OPEN_RECORDING. Добавлена обработка первого и повторного Intent, singleTop и запрос POST_NOTIFICATIONS на Android 13+.
- **Экспорт:** системный выбор файла получал `*/*` вместо MIME из эффекта. Теперь передаются MIME и имя для JSON/Markdown; отмена возвращается ViewModel.
- **Конец аудио:** STATE_ENDED делал `isReady=false` и блокировал кнопку повторного воспроизведения. Конец файла теперь остаётся доступным для воспроизведения и перемотки.
- **Сохранение записи:** оно выполняется в scope приложения, чтобы удаление экрана не оборвало завершение WAV и постановку в очередь. Повторный Stop во время сохранения игнорируется.
- **Статусы:** отменённая обработка показывалась как отсутствие речи без повтора. Теперь доступны причина ошибки, отмена/повтор, стадия и доля обработки. Старый текст не скрывает статус повторной обработки.
- **Меню:** жест закрытия захватывал устаревшее `isMenuOpen`, фон был жёстко белым. Исправлены ключи pointerInput, цвета, Back и перехват нажатий на сдвинутом экране. Для Whisper добавлены прогресс, отмена и повтор неудачной загрузки.
- **Выпуск:** добавлен tag-triggered workflow с проверкой версии, JVM-тестами, Lint, моделями, подписью, APK и SHA-256. Случайная debug-подпись release заменена постоянным ключом из Secrets. Настройка описана в RELEASE.md.

Проверки выполняются на компьютере. Физический телефон не используется; поведение микрофона, системного выбора файлов и фоновых уведомлений на устройстве этим ревью не сертифицируется. Публикация на GitHub требует отправки workflow в репозиторий, настройки секретов и push нового тега.
